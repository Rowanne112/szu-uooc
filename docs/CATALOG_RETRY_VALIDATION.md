# 闯关目录复查与任务数验收（2026-10-19）

## 已确认的原因

现场持久日志出现“课程目录部分请求失败……有限重试已耗尽：未知错误”，手动继续后可播放。另一次截图对应的是使用者主动暂停，两者已区分。

目录接口正常返回 `code:600` 和“本章为闯关模式”时，`loadUnitSources` 正确记为待解锁，但共用重试函数未清除已增加的请求计数。每完成任务重新扫描目录时，正常待解锁也会累计计数；第四次扫描不再调用服务，直接产生重试耗尽错误并暂停。这还会给正常的目录复查增加无意义退避。

界面的 `completed/total` 只统计已成功读取的任务，包含视频和章节测验，并非整门课课时。现场另有 42 个目录单元待解锁；旧首页既未解释统计范围，也未显示待解锁数量，却绘制了百分比进度条。

## 最小修复

- `retryCourseOperation` 遇到非临时错误时清掉该请求的重试计数，再将原错误交给调用方。待解锁、尚未发布仍由原业务逻辑处理；登录失效等真实错误仍会暂停，不增加自动重试。
- 网络超时、断网和 503 等临时错误继续保留既有有限重试及跨刷新预算；没有放宽重试上限。
- 目录读取中或存在待解锁单元时，首页显示“已读取任务（含视频和测验）”、待解锁数量和“总任务数待确认”，隐藏容易误解为整课进度的百分比条。不猜测未解锁章节的实际任务总数。

## 先复现，再修复

`node szu-uooc/tests/course-recovery.test.cjs` 新增真实调度链路回归：四个前置视频和一个锁定章节，逐个触发视频结束、平台确认和目录复查，最后解锁第五个视频。

修复前，在第三个视频完成后失败：`phase:paused, completed:3, total:4, error:课程目录部分请求失败……有限重试已耗尽：未知错误`。修复后通过：自动进入第五个视频，`completed:4, total:5, lockedUnits:0`。该测试不发送真实平台或解题请求。

界面回归使用现场的 `completed:6, total:7, lockedUnits:42`。修复前缺少“已读取任务”提示；修复后可见待解锁数量，隐藏百分比条，手机宽度无横向溢出。
