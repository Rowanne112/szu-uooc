# 浏览器改选修复验收（2026-10-19，v0.1.10）

## 实际原因

第一次修复 v0.1.9 只覆盖 `needsCourseRefresh: true` 的新浏览器选择。再次反馈后，只读检查现场发现：保存的 Edge 为 `needsCourseRefresh: false`，没有运行中的课程，浏览器处于连接失败状态；正在运行的控制台代码还没有 v0.1.9 的条件。

因此有两个问题：已使用过的浏览器离线后，原切换逻辑仍强制连接它核对交卷；新文件夹中的启动器遇到旧进程时，又静默打开旧控制台。

## 最小修改与安全边界

- `browser-session.mjs`：原浏览器未连接时立即返回明确的人工核对提示，不再为切换选择拉起原浏览器或等待连接超时，并标记 `requiresSubmissionConfirmation`。已发现的未确认交卷、损坏记录及页面核对失败不提供这个替代入口。
- `console-server.mjs`、`console.html`、`console.js`：无法自动核对时显示未勾选的确认框。用户必须先停止原浏览器学习，在课程网站核对上次测验结果，再明确确认，才能改选。确认不再连接旧浏览器，不删除其交卷记录，也不自动启动课程；操作写入运行记录。
- 已连接且确实有 `pendingSubmit` 的浏览器即使传入人工确认仍被拦截。运行中课程、尚未退出的工作进程、签到运行和同账号确认继续使用原保护。
- 改选后仍需连接目标浏览器并重新读取课程。课程、未知费用预留和签到历史保留；确认框在重新打开或改选目标时清空。
- `start.mjs`：启动记录保存安装目录和包清单的 SHA-256。同目录同包重复启动仍复用控制台；旧记录、其他安装目录或不同包被明确提示先退出旧控制台，不同时启动两个程序。源码测试环境没有包清单时以控制台源码计算标识。

## 红测与验证

修复前，离线已使用浏览器测试缺少人工核对入口；旧程序复用测试实际返回退出码 0，而要求为 1。

```sh
node --test --test-name-pattern='offline previously used' szu-uooc/tests/browser-selection.test.mjs
node --test --test-name-pattern='real launcher retains' szu-uooc/tests/student-start.test.mjs
```

修复后的相关回归：

```sh
node --test szu-uooc/tests/student-start.test.mjs szu-uooc/tests/browser-selection.test.mjs szu-uooc/tests/browser-session.test.mjs szu-uooc/tests/checkin.test.mjs
node --test szu-uooc/tests/browser-selection-ui.test.mjs szu-uooc/tests/console-ui.test.mjs szu-uooc/tests/user-guidance-ui.test.mjs
```

第一组 28/28 通过，第二组 4/4 通过。本机原始输出保存在 `dist/browser-switch-targeted.log` 和 `dist/browser-switch-ui.log`。

新增界面回归使用真实控制台接口和独立 Chromium，初始状态与现场一致（Edge、已完成过课程核对、保留课程、无法连接）。实际点击 Chrome → 同账号确认 → 使用此浏览器 → 显示人工核对提示 → 测试夹具明确确认 → 切换成功。验证切换选择全程没有连接原浏览器，费用预留保留，没有启动课程，重新打开确认框会清空；手机无横向溢出、无 JavaScript 错误。没有使用真实账号或付费接口。

## 用户验收

退出旧控制台，完整解压新包后启动。选择 Chrome 并保存；若原 Edge 离线且曾用于学习，会显示具体人工核对提示。先停止旧浏览器的学习并到课程网站核对上次测验结果，再勾选新增确认框后保存。之后连接 Chrome 并读取课程。

自动测试不会替用户确认真实测验是否已经提交。Windows 实机和真实课程交卷未验收；已知未确认交卷仍需处理，不能通过普通确认绕过。
